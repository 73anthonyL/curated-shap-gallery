How these plots were made

From data to model to explanation, in plain English and in technical terms.

Plain English

  1. We started with a labelled dataset. 2,999 social-media posts, each labelled by people as extremist or not extremist; 38% are extremist.
  2. We split it once and never changed the split. 2,099 posts are for training, 450 for tuning and 450 for the final test. Every model is trained, tuned and tested on the same posts.
  3. We trained 8 models, listed in the table below. Each learns from the training posts only.
  4. Each model got its own decision line. A model outputs a score from 0 to 1, how extremist it thinks a post is. Each model's cutoff for "call it extremist" was chosen on the tuning posts and then locked. The test posts were scored once at the end.
  5. We saved each trained model. Training ran on Kaggle. The trained models were downloaded for this run, and the scores they gave the test posts are saved in the research repository.
  6. 34 new posts were written by hand. 17 are meant to be extremist and 17 non-extremist, and none come from the dataset.
  7. Each downloaded model was checked before it was trusted. It re-scored 64 test posts, and its scores had to match the saved ones to within 0.01. 8 of 8 models were checked this way, and all matched.
  8. SHAP asked each model which words mattered. For each post it hid different groups of words (a hidden word becomes "...") and watched how the model's score moved, with a budget of 500 model calls per post. Each word gets a number: positive if it pushed the post toward extremist, negative if it pushed away.
  9. A waterfall shows one post under one model. It starts from the model's score when every word is hidden, adds each word's push one bar at a time, and ends at the model's actual score. The dashed line is that model's locked cutoff. 34 posts × 8 models = 272 waterfalls.
  10. A beeswarm shows one model across all the posts. It lists the words that mattered most to that model overall. Each dot is one post containing that word, placed by how hard the word pushed and coloured by the post's expected label.
  11. This site organises everything: an overview grid, one page per post and one page per model.

Technical

  1. Data. data/dataset.csv has 3,000 raw rows; processing leaves 2,999 (1 removed) with post-level binary labels: 1,129 extremist and 1,870 non-extremist. Notebook 00 reproduces the frozen split split_v1_stratified_70_15_15_seed30 (2,099 train, 450 validation, 450 test) and verifies it against the committed split file; the split is never regenerated.
  2. Models and thresholds (Kaggle). Every notebook uses one shared helper, fits on train only, chooses its decision threshold on validation only by maximising validation accuracy over a fixed grid, locks it, and evaluates the test split once. Test probabilities are committed; weights live in external storage.

  3. Research-side SHAP. Each notebook also explains test and validation posts and exports aggregated word attributions for the research questions. The curated plots here reuse the same explainer but not those files.
  4. Curated inputs. 34 hand-written texts, one per line, become curated_01 to curated_34; expected labels come from a separate file in the same order. They are not dataset rows.
  5. Restoring predictors. A loader rebuilds each notebook's predict_proba_texts from the downloaded weights and the locked threshold, reproducing each notebook's preprocessing; tests pin these to the notebooks.
  6. Verification. 64 seeded test rows are re-scored and compared with the committed test probabilities; a difference above 0.01 is refused. The table above lists each model's largest difference.
  7. Attribution. shap.Explainer(predict, shap.maskers.Text(r"\W+", mask_token="..."), algorithm="partition") with max_evals=500 and seed=30. The text masker splits a post into word tokens and builds a hierarchical partition tree over them; the partition explainer estimates Owen values (a hierarchy-respecting approximation of Shapley values) by replacing groups of words with the mask token and querying the model. Attributions are in probability units of P(extremist). 11_MULTI-CHECKPOINT_LOGIT-POOL was explained one checkpoint at a time, replaying each text against a cache of every member's log-odds (14 rounds); a test shows this reproduces explaining the whole ensemble at once.
  8. Endpoints and additivity. Per text, the base value is the model on the fully masked text and the explained output is the model on the masker's full-text reconstruction. Base value + Σ attributions = explained output; the largest observed gap is 2.3×10-6. The reconstruction drops trailing separators such as a final ".", so the explained output can differ from the probability on the raw text. The 6 of 272 waterfalls where the two differ by more than 0.005 (05_WORD-CHAR-TF-IDF_LIN-SVM: 1, 06_FASTTEXT-EMB_LOG-REG: 4, 11_MULTI-CHECKPOINT_LOGIT-POOL: 1) carry a note.
  9. Plot gate. Plotting is refused if an endpoint is missing, a value falls outside [0, 1], token positions are not exactly 0 to n−1, or base value + attributions misses the explained output by more than the plotting tolerance (0.001 by default).
  10. Waterfalls. shap.plots.waterfall on each text's token explanation, the largest bars shown and the rest grouped as "other features". The x axis is P(extremist), the base is labelled "masked" instead of E[f(X)], and a dashed line marks the locked threshold.
  11. Beeswarms. SHAP's built-in beeswarm needs one feature set shared by every sample, which text lacks, so these are drawn directly. Tokens are normalised to words and a word's occurrences within one text are summed; words are ranked by total |SHAP| across the texts, one dot per (word, text), x = SHAP value, colour = expected label, placed with a swarm layout.

The curated texts are illustrations: a handful of hand-picked posts supports no accuracy or model-ranking claim. Labels are post-level and features text-only; these models detect extremist content, not accounts or radicalisation over time. Source: extremism_sentiment_analysis.
